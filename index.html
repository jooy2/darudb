DaruDBAn embedded database for Rust, Node.js and Dart

One engine, written in Rust, keeps your application's data in a single local file. Encryption, crash safety and several processes sharing one file are designed in from the start, not added later.

Introduction
Getting started
GitHub

One engine in every language

The engine is written once, in Rust, and each language reaches it through a thin binding. A file written from Node.js reads the same from Rust or Dart, because every rule about the file lives in one place.

How it is built

Encryption of the whole file

Every page of the file is encrypted and authenticated, so a file read without its key shows nothing and a file changed without it is detected. Changing a password does not rewrite the file.

A file that survives a crash

A committed page is never overwritten in place, and a commit becomes visible by flipping a single byte. A process killed mid-write, or a power cut, leaves the last commit intact.

Several processes on one file

Processes coordinate through operating-system file locks alone, never shared memory, so a process that dies holding a lock cannot leave the others stuck.

Early development

DaruDB is in early development. The four cards above are the goals the design is built around, and each becomes a claim only when the tests and benchmarks that prove it are in the repository. Nothing is published yet, and the file format will change without a migration until the first release. Where it stands says what works today.
