Rust 변경 기록 ​

Rust 크레이트 darudb와 darudb-derive의 변경 기록이며, 최신 기록이 위에 옵니다. 패키지마다 버전을 따로 매기고 기록도 따로 둡니다. 다른 언어 패키지의 기록은 사이드바에서 언어를 바꾸면 볼 수 있습니다. 변경 기록은 패키지와 함께 관리하며 영어로 작성하므로, 아래 항목은 원문 그대로입니다.

Rust 크레이트 darudb ​

darudb vNext (2026--) ​

Changed ​

  • A sync commit on Linux, Android and the BSDs makes the file durable with fdatasync rather than fsync, which leaves out the file's times and still syncs its length with its data. A sync commit of one object takes a quarter less time for it on a GitHub-hosted Linux runner, 312 µs against 413. macOS, iOS and Windows sync as before.
  • A commit asks the file system for the file's length only when its record counts pages past both the published commit's and the last one the commit wrote, rather than at every commit. A deferred commit of one object takes 11% less time for it on a GitHub-hosted Linux runner, 22.3 µs against 25.1.

Fixed ​

  • Database::backup_with refuses a BackupOptions::password_hashing cost out of range with INVALID_ARGUMENT before it writes anything, as opening does, whether a password is given or not. With a password it failed with INTERNAL, and without one it ignored the cost.

darudb v1.1.0 (2026-10-09) ​

Breaking changes ​

  • The file format is version 6, which earlier releases cannot open. Opening a file of version 5 raises it to version 6 while no other process has it open, so a file this release has opened no longer opens with 1.0, in Rust or in any other language's package. An application that may go back to an earlier release, or that shares its file with a program still on one, opens with OpenOptions::upgrade_format(false), which also creates new files in version 5, and calls Database::upgrade_format once nothing older opens the file.

Added ​

  • OpenOptions::upgrade_format and Database::upgrade_format, which say whether opening raises a file of an older format version, and raise an open one.

Changed ​

  • An index whose entries for one value come in key order, as a non-unique index's do while the objects' primary keys grow, fills its pages as it goes, where splitting a page in the middle left half of each empty, and so do the branches of every tree. A file of 400,000 sample objects with 14 indexes is 7% smaller for it. Keys in no particular order split pages evenly, as before.
  • Database::compact first writes again, full, every tree whose pages inserts left part empty, so that the file ends about as small as a backup's copy: the same file compacts to 119 MiB rather than 140 MiB. Values in overflow runs are not written again.
  • File format 6 writes the lengths in a leaf's entries as varints rather than in five bytes. A file of 400,000 sample objects with 14 indexes takes 8% fewer pages, 126 MiB against 138, and compacts to 110 MiB against 119, with reads and writes as fast as before. A file raised from version 5 has only its header rewritten; its leaves take the new layout as writes change them, and Database::compact rewrites the trees where that saves room.

Fixed ​

  • Database::compact no longer grows the file when a value in an overflow run near the file's end finds no run of free pages below to move into. The run stays where it is, and a round of moves that would grow the file is dropped.

darudb v1.0.1 (2026-10-07) ​

Fixed ​

  • A process forked while another of its threads was opening or closing a database, or while the engine was releasing the snapshot locks it keeps for a moment, no longer hangs when it opens the file itself or ends a read transaction. The child keeps that state apart from its parent's, for up to 16 generations of processes forked one from another.

darudb v1.0.0 (2026-10-05) ​

Added ​

  • Database::open and OpenOptions open a database file, creating it when nothing exists at the path. A new file appears whole or not at all, even when two processes create it at once. Its page size is a power of two from 4096 to 65536, and the file's header is validated every time it is opened again. The file format version is 5.
  • Database::begin_read and Database::begin_write start transactions over named trees of byte keys and byte values. ReadTransaction sees one commit for as long as it lives, whatever is committed after it began. WriteTransaction adds insert, remove and delete_tree, sees its own changes, and makes all of them visible and durable at once with commit; dropping it aborts it. Both offer get, range, range_backward, iter, len and tree_names.
  • A commit is durable when commit returns: a crash or a power cut at any moment leaves the file at a commit no older than the last one that returned. Opening a file after a crash recovers it without a separate step.
  • Every page is verified against the check its parent recorded before it is used, so a damaged or stale page is reported as CORRUPTED rather than read.
  • A value too large to keep in a tree's pages is stored in pages of its own, up to 4 GiB.
  • Database handles to one file in a process share one instance, so they see the same commits and take turns writing. OpenOptions::busy_timeout sets how long begin_write waits for another writer.
  • Error reports every failure with a stable code: IO, NOT_FOUND, NOT_A_DATABASE, UNSUPPORTED_FORMAT_VERSION, CORRUPTED, INVALID_ARGUMENT, CLOSED, BUSY, SYNC_FAILED and INTERNAL. CLOSED is for a language binding's handle used after it was closed; SYNC_FAILED means a barrier failed, the last commit's outcome is unknown, and the file has to be opened again.
  • WriteTransaction::commit_deferred publishes a commit without waiting for a barrier. Readers see it at once; it becomes durable at the next commit, at Database::sync, when the database is closed, or when OpenOptions::max_unsynced_time (one second by default) or OpenOptions::max_unsynced_pages runs out. The limits count the deferred commits of every process since the last barrier. A crash of the process loses no deferred commit, and a power cut undoes them only from the newest backwards. Pages that deferred commits write and stop using again are reused before the window ends once no reader needs them, so a run of small deferred commits does not grow the file.
  • Database::close makes deferred commits durable first, and reports whether a barrier failed on any handle to the file.
  • OpenOptions::key and OpenOptions::password create an encrypted database, or open one. Every page is encrypted and authenticated under a random data key, which the key, or the Argon2id hash of the password, wraps: with XAES-256-GCM on processors with AES instructions, and XChaCha20-Poly1305 elsewhere. OpenOptions::password_hashing sets the Argon2id cost, 19 MiB, 2 iterations and 1 lane by default.
  • Each commit record of an encrypted database carries a MAC under a key derived from the data key, so a record put together from the file's own pages by someone without the key is refused.
  • Database::set_key and Database::set_password change the key of an encrypted database without encrypting any page again, and Database::is_encrypted tells the two kinds of database apart.
  • The error codes KEY_REQUIRED, for an encrypted database opened without a key or password, and WRONG_KEY, for one that does not open it.
  • Several processes can open one database file at once, coordinated through the operating system's byte-range locks and nothing else. One process writes at a time and begin_write waits for another process's writer as it does for its own, readers never wait for a writer, and a process that dies releases its locks with nothing left for the others to clean up. The first process to open a file recovers it, and one that opens it meanwhile waits up to the busy timeout. Database::sync makes deferred commits durable whichever process made them.
  • The error code UNSUPPORTED_FILE_SYSTEM, for a database on a network file system such as NFS or SMB, or on one whose file locks do not work. Network file systems are recognised on Linux, Android, macOS, iOS and Windows, on a best-effort basis, and a new database is refused before its file is created.
  • Collections of typed objects. OpenOptions::schema declares a Schema of Collections, each with fields of a Type, a primary key that is a declared field or an auto-increment, and indexes, unique or not. The first open stores the schema in the file, and every later open compares it with the stored one. ReadTransaction::collection and WriteTransaction::collection read and write Objects of Values: insert, put, delete, get, iter and len, with every index kept in step in the same transaction. A write the schema or a unique index refuses leaves the transaction able to commit.
  • Migrations. A schema carries a version, and opening a file that holds an older one migrates it in one write transaction: the engine adds collections, fields and indexes and removes what the schema no longer has, and a Migration registered with OpenOptions::migration renames collections and fields, replaces fields, deletes collections, and runs a function that moves data, reading the old objects through Migrating::previous.
  • Queries. CollectionReader::query and CollectionWriter::query return the objects a Query finds, and count counts them. A Filter tests fields, fields of embedded objects and fields of linked objects with comparisons, between, is_in, contains, starts_with, ends_with and null tests, combined with and, or and !; a query sorts by any number of fields and takes an offset and a limit. A condition on the primary key or an indexed field reads only the objects that meet it, and a sort on an indexed field alone stops reading at the limit. The error code INVALID_QUERY reports a query that names a missing field or compares a field with a value of another type.
  • Query::parse reads a query written in the query language, such as age >= $0 AND name STARTSWITH "A" SORT BY age DESC LIMIT 10, with parameters for $0, $1 and on, into the same query the builder makes. Text that does not parse fails with INVALID_QUERY, naming the character where it went wrong.
  • OpenOptions::cache_size sets how much memory the page cache of a file may take, in bytes: 32 MiB by default, and never fewer than 16 pages. The cache fills only as pages are read.
  • Query::prepare parses a query once and keeps its parameters, and Query::bind gives them values, for a query that runs many times; Query::bind_encoded takes them encoded in one record, as a language binding sends them. A query run with a parameter that has no value fails with INVALID_QUERY.
  • The byte formats language bindings exchange with the engine: CollectionReader::get_record, CollectionWriter::insert_record and put_record, and query_records carry objects as records, which get_record_with and query_records_with lend where they lie rather than copying each into a vector; QueryRequest reads and writes a query as IR; Database::schema_record gives the stored schema as its record; and Schema::decode reads a schema declared in another language.
  • Query::first keeps only the first object a query finds, and stops reading there.
  • OpenOptions::open_migrating opens a database whose migration stops for the caller between its version steps, as a PendingMigration, so that a binding can run migration functions written in its own language in the migration's write transaction. PendingMigration::previous_schema_record and Migrating::previous_record give a binding the old schema and the old objects as records, and PendingMigration::schema_record and transaction the new schema and the migration's write transaction.
  • The error codes SCHEMA_MISMATCH, for a schema changed without a new version or a file migrated under an open handle, SCHEMA_TOO_NEW, for a file a newer application wrote, DUPLICATE_KEY and MIGRATION_FAILED. UNSUPPORTED_FORMAT_VERSION also reports a stored schema in an object format a newer build wrote.
  • CollectionWriter::update sets the fields it is given in the object with a key and keeps the rest, going down the collection's tree once, and returns whether there was an object. The object becomes what put would write for the stored object with those fields set: Value::Null makes an optional field null and gives a field with a default its default. Changing the primary key fails with INVALID_ARGUMENT. CollectionWriter::update_record takes the changes as a record, as a language binding sends them, in which the tag 0x01 makes a field null; in a collection whose fields all hold scalars it changes the stored record where it lies and reads only the indexes on the fields it changes.
  • Database::check, the integrity check: every page the published commit reaches against its check, the order of every key, every tree's count, that every page of the file is used, free or retained exactly once, and in a file with a schema every object against its indexes. It returns a CheckReport of every Problem it finds, and reads the commit a read transaction sees, so other handles and processes may write meanwhile.
  • Database::backup, a copy of the published commit in a new file, written while other handles and processes go on using the database. The copy holds no free space, has the file's page size, and opens with the same key or password. It appears at the path only once it is whole and durable, and never replaces a file already there. It returns a BackupReport.
  • Database::backup_with and BackupOptions write a backup under a new random data key, which a key or a password given for the copy wraps. Changing a file's key or password leaves its data key as it was, so this is how a data key that may have been exposed is left behind; a plain database's copy is encrypted the same way.
  • Database::compact, which makes the file smaller in place, while other handles and processes go on using it: write transactions move the pages at the end of the file into free pages nearer its start, and the commits after them give the end back to the file system. It returns a CompactReport.
  • OpenOptions::salvage, which rescues what it can of a damaged file into a new one. It reads the file page by page, so it works on a file that does not open, starts from the newest commit it records, and takes what that commit cannot read from older versions of the same pages where the file still has them. The new file gets its indexes built again from its objects, passes the integrity check, and opens with the same key or password. It needs the file alone, so an open file fails with BUSY, and it returns a SalvageReport of what it rescued and what it could not.
  • Objects as Rust types. With the derive feature, #[derive(Object)] makes a struct the objects of a collection and #[derive(Embedded)] makes one an embedded object, with #[darudb(...)] attributes for the key, indexes, field names and defaults. Collection::of declares the collection from the type, and ReadTransaction::collection_of, WriteTransaction::collection_of and Migrating::collection_of give a TypedReader or TypedWriter that reads records straight into the type and writes it as records, without building an Object. Link<T> is a link typed by its target. The traits CollectionType, EmbeddedType, FieldType, ElementType and KeyType, with FieldReader, ValueReader and ValueWriter, can be implemented by hand without the feature. A type whose fields do not match the stored collection fails with INVALID_ARGUMENT.
