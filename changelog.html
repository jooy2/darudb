Changelog ​

Each package versions on its own and keeps its own history. This page shows all of them, newest first within each.

Rust crate darudb ​

Rust vNext (2026--) ​

Added ​

  • Database::open and OpenOptions open a database file, creating it when nothing exists at the path. A new file appears whole or not at all, even when two processes create it at once. Its page size is a power of two from 4096 to 65536, and the file's header is validated every time it is opened again.
  • Database::begin_read and Database::begin_write start transactions over named trees of byte keys and byte values. ReadTransaction sees one commit for as long as it lives, whatever is committed after it began. WriteTransaction adds insert, remove and delete_tree, sees its own changes, and makes all of them visible and durable at once with commit; dropping it aborts it. Both offer get, range, range_backward, iter, len and tree_names.
  • A commit is durable when commit returns: a crash or a power cut at any moment leaves the file at a commit no older than the last one that returned. Opening a file after a crash recovers it without a separate step.
  • Every page is verified against the check its parent recorded before it is used, so a damaged or stale page is reported as CORRUPTED rather than read.
  • A value too large to keep in a tree's pages is stored in pages of its own, up to 4 GiB.
  • Database handles to one file in a process share one instance, so they see the same commits and take turns writing. OpenOptions::busy_timeout sets how long begin_write waits for another writer.
  • Error reports every failure with a stable code: IO, NOT_FOUND, NOT_A_DATABASE, UNSUPPORTED_FORMAT_VERSION, CORRUPTED, INVALID_ARGUMENT, CLOSED, BUSY, SYNC_FAILED and INTERNAL. CLOSED is for a language binding's handle used after it was closed; SYNC_FAILED means a barrier failed, the last commit's outcome is unknown, and the file has to be opened again.
  • WriteTransaction::commit_deferred publishes a commit without waiting for a barrier. Readers see it at once; it becomes durable at the next commit, at Database::sync, when the database is closed, or when OpenOptions::max_unsynced_time (one second by default) or OpenOptions::max_unsynced_pages runs out. A crash of the process loses no deferred commit, and a power cut undoes them only from the newest backwards. Pages that deferred commits write and stop using again are reused before the window ends once no reader needs them, so a run of small deferred commits does not grow the file.
  • Database::close makes deferred commits durable first, and reports whether a barrier failed on any handle to the file.
  • OpenOptions::key and OpenOptions::password create an encrypted database, or open one. Every page is encrypted and authenticated under a random data key, which the key, or the Argon2id hash of the password, wraps: with XAES-256-GCM on processors with AES instructions, and XChaCha20-Poly1305 elsewhere. OpenOptions::password_hashing sets the Argon2id cost, 19 MiB, 2 iterations and 1 lane by default.
  • Each commit record of an encrypted database carries a MAC under a key derived from the data key, so a record put together from the file's own pages by someone without the key is refused. The file format version is 3.
  • Database::set_key and Database::set_password change the key of an encrypted database without encrypting any page again, and Database::is_encrypted tells the two kinds of database apart.
  • The error codes KEY_REQUIRED, for an encrypted database opened without a key or password, and WRONG_KEY, for one that does not open it.
  • Several processes can open one database file at once, coordinated through the operating system's byte-range locks and nothing else. One process writes at a time and begin_write waits for another process's writer as it does for its own, readers never wait for a writer, and a process that dies releases its locks with nothing left for the others to clean up. The first process to open a file recovers it, and one that opens it meanwhile waits up to the busy timeout. Database::sync makes deferred commits durable whichever process made them.
  • The error code UNSUPPORTED_FILE_SYSTEM, for a database on a network file system such as NFS or SMB, or on one whose file locks do not work. Network file systems are recognised on Linux, Android, macOS, iOS and Windows, on a best-effort basis, and a new database is refused before its file is created.
  • Collections of typed objects. OpenOptions::schema declares a Schema of Collections, each with fields of a Type, a primary key that is a declared field or an auto-increment, and indexes, unique or not. The first open stores the schema in the file, and every later open compares it with the stored one. ReadTransaction::collection and WriteTransaction::collection read and write Objects of Values: insert, put, delete, get, iter and len, with every index kept in step in the same transaction. A write the schema or a unique index refuses leaves the transaction able to commit.
  • Migrations. A schema carries a version, and opening a file that holds an older one migrates it in one write transaction: the engine adds collections, fields and indexes and removes what the schema no longer has, and a Migration registered with OpenOptions::migration renames collections and fields, replaces fields, deletes collections, and runs a function that moves data, reading the old objects through Migrating::previous.
  • Queries. CollectionReader::query and CollectionWriter::query return the objects a Query finds, and count counts them. A Filter tests fields, fields of embedded objects and fields of linked objects with comparisons, between, is_in, contains, starts_with, ends_with and null tests, combined with and, or and !; a query sorts by any number of fields and takes an offset and a limit. A condition on the primary key or an indexed field reads only the objects that meet it, and a sort on an indexed field alone stops reading at the limit. The error code INVALID_QUERY reports a query that names a missing field or compares a field with a value of another type.
  • Query::parse reads a query written in the query language, such as age >= $0 AND name STARTSWITH "A" SORT BY age DESC LIMIT 10, with parameters for $0, $1 and on, into the same query the builder makes. Text that does not parse fails with INVALID_QUERY, naming the character where it went wrong.
  • OpenOptions::cache_size sets how much memory the page cache of a file may take, in bytes: 32 MiB by default, and never fewer than 16 pages. The cache fills only as pages are read.
  • Query::prepare parses a query once and keeps its parameters, and Query::bind gives them values, for a query that runs many times; Query::bind_encoded takes them encoded in one record, as a language binding sends them. A query run with a parameter that has no value fails with INVALID_QUERY.
  • The byte formats language bindings exchange with the engine: CollectionReader::get_record, CollectionWriter::insert_record and put_record, and query_records carry objects as records, which get_record_with and query_records_with lend where they lie rather than copying each into a vector; QueryRequest reads and writes a query as IR; Database::schema_record gives the stored schema as its record; and Schema::decode reads a schema declared in another language.
  • Query::first keeps only the first object a query finds, and stops reading there.
  • OpenOptions::open_migrating opens a database whose migration stops for the caller between its version steps, as a PendingMigration, so that a binding can run migration functions written in its own language in the migration's write transaction. PendingMigration::previous_schema_record and Migrating::previous_record give a binding the old schema and the old objects as records, and PendingMigration::schema_record and transaction the new schema and the migration's write transaction.
  • The error codes SCHEMA_MISMATCH, for a schema changed without a new version or a file migrated under an open handle, SCHEMA_TOO_NEW, for a file a newer application wrote, DUPLICATE_KEY and MIGRATION_FAILED. UNSUPPORTED_FORMAT_VERSION also reports a stored schema in an object format a newer build wrote.
  • CollectionWriter::update sets the fields it is given in the object with a key and keeps the rest, going down the collection's tree once, and returns whether there was an object. The object becomes what put would write for the stored object with those fields set: Value::Null makes an optional field null and gives a field with a default its default. Changing the primary key fails with INVALID_ARGUMENT. CollectionWriter::update_record takes the changes as a record, as a language binding sends them, in which the tag 0x01 makes a field null; in a collection whose fields all hold scalars it changes the stored record where it lies and reads only the indexes on the fields it changes.
  • Database::check, the integrity check: every page the published commit reaches against its check, the order of every key, every tree's count, that every page of the file is used, free or retained exactly once, and in a file with a schema every object against its indexes. It returns a CheckReport of every Problem it finds, and reads the commit a read transaction sees, so other handles and processes may write meanwhile.
  • Database::backup, a copy of the published commit in a new file, written while other handles and processes go on using the database. The copy holds no free space, has the file's page size, and opens with the same key or password. It appears at the path only once it is whole and durable, and never replaces a file already there. It returns a BackupReport.
  • Database::compact, which makes the file smaller in place, while other handles and processes go on using it: write transactions move the pages at the end of the file into free pages nearer its start, and the commits after them give the end back to the file system. It returns a CompactReport.
  • OpenOptions::salvage, which rescues what it can of a damaged file into a new one. It reads the file page by page, so it works on a file that does not open, starts from the newest commit it records, and takes what that commit cannot read from older versions of the same pages where the file still has them. The new file gets its indexes built again from its objects, passes the integrity check, and opens with the same key or password. It needs the file alone, so an open file fails with BUSY, and it returns a SalvageReport of what it rescued and what it could not.
  • Objects as Rust types. With the derive feature, #[derive(Object)] makes a struct the objects of a collection and #[derive(Embedded)] makes one an embedded object, with #[darudb(...)] attributes for the key, indexes, field names and defaults. Collection::of declares the collection from the type, and ReadTransaction::collection_of, WriteTransaction::collection_of and Migrating::collection_of give a TypedReader or TypedWriter that reads records straight into the type and writes it as records, without building an Object. Link<T> is a link typed by its target. The traits CollectionType, EmbeddedType, FieldType, ElementType and KeyType, with FieldReader, ValueReader and ValueWriter, can be implemented by hand without the feature. A type whose fields do not match the stored collection fails with INVALID_ARGUMENT.

Rust derive vNext (2026--) ​

  • #[derive(Object)], which implements darudb::CollectionType for a struct with named fields, and #[derive(Embedded)], which implements darudb::EmbeddedType and darudb::FieldType. They read #[darudb(collection = "...")] on the struct, and key, index, unique, rename = "..." and default = ... on a field.

Node.js package darudb ​

Node.js vNext (2026--) ​

Added ​

  • Database.open opens a database file, creating it when nothing exists at the path, with create and pageSize options. path, isOpen, pageSize and formatVersion describe the open database, and close flushes and closes it.
  • Every error thrown by the package carries the engine's stable code, such as NOT_FOUND, NOT_A_DATABASE or CLOSED.
  • Several processes can open one database file at once, coordinated through the engine's file locks. A database on a network file system is refused with UNSUPPORTED_FILE_SYSTEM.
  • engineVersion() and FORMAT_VERSION report the engine inside the package and the file format version it reads and writes.
  • Collections of objects under a schema declared with t, collection and schema, passed to Database.open as schema. TypeScript infers every object's type from the declaration. db.read(fn) and db.write(fn) run a function in a transaction, committing a write when the function returns and aborting it when it throws, with durability: 'deferred' to commit without waiting for the disk. A collection offers get, find, findOne, count, insert, insertMany, put, putMany and delete, and objects cross into the engine as records, a batch in one call. A property the schema does not have is refused, and so is a modifier on a list's element, such as t.list(t.string().index()), rather than dropped: an index goes on the list itself. t.bigint() declares an int read as a bigint, write transactions on one file do not nest, even through two Database objects or from a migration function, and busyTimeout sets how long a write waits for another process.
  • Queries built with where, sortBy, limit and offset, typed by the collection's fields, or written in the query language with parameters. conditions and Query build filters outside a collection.
  • The cacheSize option of Database.open and Database.openAsync sets how much memory the page cache of a file may take, in bytes: 32 MiB by default.
  • Prepared queries: db.prepare(collection, query) parses a query once, as text or built with param in place of values, and find, findOne and count run it with its parameters' values, in synchronous and asynchronous transactions. The package also keeps up to 256 texts it has parsed, so a text query run again with other parameters is not parsed again.
  • Migrations: raising the schema's version migrates the file when it opens, with the renames, deletions and replaced fields a migration lists and a JavaScript function that reads the objects as they were through previous and previousKeys.
  • db.schemaVersion, and db.sync() to make deferred commits durable.
  • The package is written in TypeScript, and its type declarations are generated from its source. They name the types of t, Database and Query as TypeBuilders, DatabaseOpener and QueryConstructor.
  • An asynchronous API: Database.openAsync, readAsync, writeAsync, syncAsync and closeAsync do the engine's work on the libuv thread pool and resolve promises, so the event loop never waits for the disk or for another process's writer. Their transaction functions and migration functions may be asynchronous, every collection method returns a promise, and a transaction runs its operations in the order they were called and commits once they have all settled. Operations called together, or while earlier ones are on the pool, cross into the engine as one batch in one trip, and readAsync begins its read on the calling thread, since a read waits for no writer. This process's writes on one file queue in JavaScript rather than on the pool, however each handle named the file, a hard link on Windows included, syncAsync and closeAsync with them, and a synchronous write, sync or close while an asynchronous write holds the file fails with INVALID_ARGUMENT rather than blocking the event loop.
  • update(key, changes) on the collections of synchronous and asynchronous write transactions sets the fields it is given, keeps the rest, and says whether there was an object. null makes an optional field null and gives a field with a default its default, and a field left undefined stays as it is. Only the changed fields cross into the engine, which changes the stored record where it lies, so updating a field costs less than reading the object and putting it back.
  • db.check() and db.checkAsync(), the integrity check of the published commit, which report every problem they find, each with its page and its tree or collection, rather than throwing.
  • db.backup(path) and db.backupAsync(path), a copy of the published commit in a new file, which the same key or password opens and which never replaces a file already at the path.
  • db.compact() and db.compactAsync(), which make the file smaller in place. Like a write, compactAsync waits its turn after this process's other writes on the file, and compact is refused while one of them holds it.
  • Database.salvage(from, into) and Database.salvageAsync(from, into), which rescue what they can of a damaged file into a new one, and report what they rescued and what they could not. They work on a file that does not open, need it alone, so a file in use fails with BUSY, and never replace a file already at into.
  • Encryption: key or password in the options of open, openAsync and Database.salvage encrypts a new database or opens an encrypted one, passwordHashing sets the cost of hashing a password, db.isEncrypted tells the two kinds of file apart, and setKey, setPassword and their Async twins change the key. Opening an encrypted database without its key fails with KEY_REQUIRED, and with another one with WRONG_KEY.
  • Electron's main process is supported, and the tests run the package there, in Electron 44. The guide says how several Electron processes share one file and how to keep the addon outside an asar archive.
  • Every platform package ships LICENSE and THIRD_PARTY_NOTICES.txt, the licences of the Rust crates and of the C source linked into its addon.

Dart package darudb ​

Dart vNext (2026--) ​

Added ​

  • Database.open opens or creates a database file, with a Schema of the collections darudb_generator generates from classes annotated @Collection() and @Embedded(), and the options create, pageSize, busyTimeout, cacheSize, key, password and passwordHashing. A file holding an older schema version is migrated in one write transaction, through the Migrations registered for the versions in between, whose functions read the old objects through MigrationContext.
  • Database.read and Database.write run a function in a transaction; write commits when it returns, deferred with Durability.deferred, and aborts when it throws. txn.collection(userSchema) gives a collection's objects as the annotated class: get, find, findOne and count with a typed query builder whose conditions combine with &, | and ~, findText for the query language, Database.prepare and findPrepared, and in a write insert, insertMany, put, putMany, update and delete. update takes a change for each field it sets, made by the field's set, an embedded object's included, which it replaces whole.
  • Database.sync, Database.close, setKey, setPassword, isEncrypted, pageSize, formatVersion and schemaVersion. Every failure is a DaruException with the engine's error code.
  • The Future API: Database.openAsync, readAsync, writeAsync, syncAsync, closeAsync, setKeyAsync and setPasswordAsync, whose transactions give collections of Future-returning calls. The engine's work runs on threads of the native library, and the result comes back on the isolate's event loop. The calls of one transaction run in the order they were made; an isolate's asynchronous writes on one file take turns, and a synchronous write, sync or close on the file while one runs is refused with INVALID_ARGUMENT.
  • The tools, each with an Async twin: check, the integrity check, which reports every problem in a CheckReport; backup, a copy of the published commit in a new file; compact, which makes the file smaller in place; and Database.salvage, which rescues what it can of a damaged file into a new one, with a key or a password for an encrypted file.
  • The build hook downloads the native library for the application's target from the package's GitHub release, and uses it only when its SHA-256 hash is the one hook/prebuilt.json names, so building an application needs no Rust toolchain. A download is kept in the hook's cache. In a checkout of the repository, which an application gets by depending on the package through git or a path, the hook builds the engine from source with native_toolchain_rust instead.

Dart package darudb_generator ​

Dart generator vNext (2026--) ​

Added ​

  • The builder darudb, which writes for each class annotated @Collection() its schema constant, record codec, query builder, link type and copyWith, and for each class annotated @Embedded() its schema constant, codec, query fields and copyWith, into the library's .g.dart part. It refuses a class it cannot store with an error that names the field: a field that is not final, a type the database does not store, a nullable field with a default, two primary keys, a collection without a key and without int? id, or an index inside an embedded object.
