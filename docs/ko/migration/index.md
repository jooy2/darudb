# 다른 데이터베이스에서 옮기기

지금 쓰는 임베디드 데이터베이스에서 애플리케이션의 데이터를 DaruDB로 옮기는 방법을 데이터베이스마다 한 페이지씩 정리했습니다.

DaruDB 파일의 스키마를 바꾸는 방법은 가이드의 [마이그레이션](../guide/migrations.md)에 있습니다.

## 옮기는 순서

모든 가이드가 같은 네 단계를 따르고, 원래 파일은 건드리지 않습니다.

1. **스키마를 선언합니다.** 원래 데이터베이스가 담던 것을 담을 수 있게 테이블이나 클래스마다 컬렉션을, 열이나 속성마다 필드를 둡니다. 가이드마다 무엇이 무엇에 대응하는지, 아직 대응하는 것이 없는 것은 무엇인지 표로 정리했습니다.
1. **데이터를 복사합니다.** 원래 파일을 그 라이브러리로 읽기 전용으로 열고, 새 DaruDB 파일에 객체를 쓰는 코드를 돌립니다. 레코드의 키를 객체의 키로 그대로 옮기면 레코드 사이의 참조가 모두 링크로 살아남습니다.
1. **복사본을 확인합니다.** 테이블이나 클래스마다 레코드 수를 컬렉션의 객체 수와 비교하고, 새 파일에 [무결성 검사](../guide/tools.md#파일-검사하기)를 돌립니다.
1. **애플리케이션이 새 파일을 쓰게 바꿉니다.** 원래 파일은 애플리케이션이 새 파일로 한동안 문제없이 돈 뒤에 정리합니다.

## 복사는 어디서 하나

서버의 데이터는 한곳에 있으니 스크립트로 한 번 복사하면 됩니다. 앱의 데이터는 기기마다 있으므로, 복사는 앱 안에서 합니다. 옮기는 버전이 처음 실행될 때, 원래 파일을 열기 전에 한 번 합니다. Dart 가이드가 이렇게 합니다. 복사본은 `app.darudb.part`라는 다른 이름으로 쓰고 닫은 뒤에 제자리로 이름을 바꾸므로, 충돌하거나 앱을 닫아서 끊긴 복사는 다음 실행 때 처음부터 다시 합니다. 원래 파일은 그다음 버전에서야 지웁니다. 다른 언어의 코드도 같은 방법으로 중간에 끊겨도 안전하게 만들 수 있습니다.

## 빠르게 복사하기

- **트랜잭션 하나에 객체 여럿.** 복사 코드는 쓰기 트랜잭션마다 객체를 천 개씩 씁니다. 객체마다 커밋하지 않고 천 개에 커밋 한 번으로 끝납니다.
- **지연 커밋으로 쓰고 마지막에 닫기.** 트랜잭션마다 디스크를 기다리지 않고 커밋하고, 마지막에 데이터베이스를 닫을 때 한꺼번에 디스크에 기록합니다. 어떤 이유로든 복사가 중간에 멈추면 그 파일을 지우고 다시 복사하면 되므로, 기다리지 않아도 잃는 것이 없습니다.
- **순서는 상관없습니다.** 링크는 아직 없는 객체를 가리켜도 되므로 컬렉션을 어떤 순서로 복사해도 됩니다.

## 가이드

사이드바에서 고른 언어의 가이드입니다.

::: lang rust

- [SQLite](./sqlite.md): 테이블과 행, 인덱스. `rusqlite`로 읽습니다.
- [LMDB](./lmdb.md): 바이트를 담는 이름 있는 데이터베이스. `heed`로 읽습니다.
- [redb](./redb.md): 타입이 정해진 테이블과 멀티맵 테이블.
- [sled](./sled.md): 바이트를 담는 트리.

:::

::: lang node

- [SQLite](./sqlite.md): 테이블과 행, 인덱스. `node:sqlite`로 읽습니다.
- [Realm](./realm.md): 객체 스키마와 링크, 내장 객체. `realm`으로 읽습니다.
- [LMDB](./lmdb.md): 이름 있는 데이터베이스. `lmdb`로 읽습니다.
- [LevelDB](./level.md): JSON 값을 담는 서브레벨. `classic-level`로 읽습니다.

:::

::: lang dart

- [SQLite](./sqlite.md): 테이블과 행, 인덱스. Flutter 앱 안에서 `sqflite`로 읽습니다.
- [Realm](./realm.md): 객체 스키마와 링크, 내장 객체. Flutter 앱 안에서 `realm`으로 읽습니다.
- [Hive](./hive.md): 박스와 타입 어댑터. Flutter 앱 안에서 `hive_ce`로 읽습니다.

:::

::: lang python

- [SQLite](./sqlite.md): 테이블과 행, 인덱스. `sqlite3`로 읽습니다.
- [LMDB](./lmdb.md): 바이트를 담는 이름 있는 데이터베이스. `lmdb`로 읽습니다.
- [TinyDB](./tinydb.md): JSON 문서를 담는 테이블.
- [shelve](./shelve.md): pickle한 값을 담는 셸프.

:::
