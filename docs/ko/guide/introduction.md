# 소개

DaruDB는 애플리케이션의 데이터를 로컬 파일 하나에 담는 임베디드 데이터베이스이며, Rust로 작성한 엔진 하나를 Rust와 Node.js, Dart 프로그램이 함께 씁니다.

임베디드 데이터베이스는 프로그램 옆이 아니라 프로그램 안에서 돌아갑니다. 설치하거나 띄우거나 접속할 서버가 없습니다. 프로그램이 파일을 열고, 그 안에 객체를 읽고 쓰고, 파일을 닫으면 끝입니다. 데스크톱 애플리케이션이나 모바일 앱, 명령줄 도구, 작은 서버가 자기 데이터를 보관할 때 쓰는 종류의 데이터베이스입니다.

## 패키지

| 패키지 | 언어 | 정체 |
| --- | --- | --- |
| `darudb` 크레이트 | Rust | 엔진 그 자체이자, Rust 프로그램이 바로 가져다 쓰는 라이브러리 |
| `darudb` npm 패키지 | Node.js | 엔진 위의 바인딩. 타입이 걸린 TypeScript API를 동기와 비동기로 제공 |
| `darudb` Dart 패키지 | Dart | Flutter 앱과 Dart 프로그램을 위한 엔진 위의 바인딩. 동기 API와 `Future` API를 제공하고, 생성기 `darudb_generator`가 어노테이션을 붙인 클래스를 저장할 수 있게 해 줌 |

Rust 크레이트는 다른 패키지가 올라서는 코어에 그치지 않습니다. Node.js 프로그램이 npm 패키지에 의존하듯 Rust 프로그램도 이 크레이트에 의존하고, 컬렉션과 쿼리, 마이그레이션, 도구를 똑같이 씁니다. 바인딩에 없는 것도 두 가지 있습니다. 객체 아래에서 이름 붙은 바이트 트리를 다루는 [저장 커널](../engine/storage-kernel.md)과, [바인딩을 만들 때 쓰는 호출](../engine/bindings.md)입니다.

사이드바 맨 위의 선택기에서 쓰는 언어를 고르세요. 모든 페이지의 예제와 API, 타입 섹션이 그 선택을 따르고, 사이트는 고른 언어를 기억합니다.

## 설계 목표

모든 결정은 다섯 가지 요구 사항을 따르며, 우선순위도 이 순서입니다.

1. **성능.** 애플리케이션이 흔히 쓰는 임베디드 SQL 엔진보다 빠른 읽기와 쓰기. 같은 내구성 설정에서 측정합니다.
1. **암호화.** 파일 전체를 암호화하고 인증하며, 키를 올바르게 만들고 보관합니다.
1. **안정성.** 크래시나 정전을 겪어도 살아남는 파일, 손상을 알아채고 복구할 수 있는 구조, 여러 프로세스가 파일 하나를 동시에 쓰는 환경.
1. **호환성.** Windows와 macOS, Linux, iOS, Android의 오래된 버전부터 최신 버전까지. 파일 형식은 자기 버전을 기록하고, 파일 형식이나 스키마의 새 버전마다 이전 버전에서 넘어오는 마이그레이션을 함께 제공합니다.
1. **쓰기 쉬움.** 스키마를 선언하기 쉽고 쿼리를 작성하기 쉬우며, 결과는 열린 데이터베이스에 묶인 핸들이 아니라 평범한 객체입니다.

모두 목표입니다. 각 목표는 그것을 증명하는 벤치마크나 테스트가 저장소에 들어온 뒤에야 기능이라고 말합니다.

## 구조

엔진은 Rust로 한 번만 작성하고, Node.js와 Dart 패키지는 그 위의 얇은 바인딩으로서 자기만의 동작을 더하지 않습니다. 파일에 관한 규칙은 모두 엔진에 있습니다. 그래서 한 언어에서 쓴 파일을 다른 언어에서 읽어도 똑같이 읽히고, 오류도 모든 언어에서 같은 `code`를 갖습니다. 엔진의 계층은 [엔진 구조](../engine/architecture.md)에서 차례로 살펴봅니다.

## 현재 상태

- **저장.** 쓰기 시 복사 방식의 페이지 트리입니다. 페이지마다 쓰기 전에 부모가 기록해 둔 체크와 대조하므로, 손상된 페이지는 그대로 읽지 않고 손상됐다고 알립니다. 커밋은 반환되는 순간 내구성을 갖고, 지연 커밋은 디스크를 기다리지 않고 반환한 뒤 기본값으로 1초 안에 디스크에 기록됩니다.
- **암호화.** 키나 비밀번호로 만든 데이터베이스는 모든 페이지가 암호화되고 인증됩니다. 비밀번호를 바꿔도 다시 암호화하는 페이지는 없습니다.
- **여러 프로세스.** 프로세스끼리는 운영체제의 파일 잠금만으로 파일 하나를 함께 씁니다. 쓰는 쪽은 한 번에 하나이고, 읽는 쪽은 기다리지 않으며, 프로세스가 죽어도 남는 것이 없습니다.
- **객체.** 스키마와 컬렉션, 인덱스, 링크와 내장 객체, 코드로 만들거나 문자열로 쓰는 쿼리, 그리고 스키마 버전 사이의 마이그레이션이 있습니다.
- **도구.** 무결성 검사와 온라인 백업, 압축, 손상된 파일 되살리기가 있습니다.
- **테스트.** 정전 시뮬레이션 수천 번과 커밋 도중의 실제 프로세스 강제 종료 수백 번을 암호화를 켜고 끈 두 경우 모두 통과합니다. 여러 프로세스가 파일 하나를 함께 읽고 쓰는 동안 무작위로 강제 종료하는 시험도 통과합니다.
- **패키지.** Rust 크레이트와 Node.js 패키지, Dart 패키지 모두 위의 기능을 다 갖췄고, 셋 다 배포했습니다. Node.js와 Dart 패키지에는 지원하는 모든 플랫폼용으로 엔진을 미리 빌드해 넣었으므로 Rust 컴파일러 없이 설치됩니다.
